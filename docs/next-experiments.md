# Next experiments

The current goal is RL feasibility for FHIR querying and full CRUD, progressing toward an EHR search agent. This revision focuses on local benchmark/environment design; training and external publication are deferred.

1. Review clinical and clerical examples, including the new discovery variants. Expand terminology, chart topology, specialties and contradictions with source notes before expanding patient count. Keep known generator missingness separate from undocumented real-world events.
2. Freeze patient-separated train/dev task cohorts, chart checksums, difficulty annotations, allowed writes and budgets. Use all CRUD families; compare raw and assisted access on identical cases, with a separate restricted supplied-chart read-only control. Add a family holdout if claiming unseen-workflow generalization.
3. Establish step-zero baselines, then evaluate the same dev tasks at fixed checkpoints. Analyze strict success and search behavior alongside turns/tokens by difficulty and CRUD mix. Reference traces verify the compiler, rather than agent learning. Use the [metric protocol](metrics-and-evaluation.md) and recorded usage only.
4. Test whether RL learns to spend more on harder tasks and less on unnecessary retrieval. Compare within family/CRUD mix and account for evidence count, output length and write work. Linear scaling and longer, more targeted queries are hypotheses. Efficiency gains must retain correctness.
5. Before future interoperability experiments, run the official full FHIR validator and reference traces against an independent R4 server. Replace the simulator with an adapter where appropriate. Actual SQL-on-FHIR ViewDefinition conformance, array lineage and equivalent absence proofs remain separate work.
6. When training resumes, consider valid-action demonstrations before RL, then increase search dependencies and write coordination. Keep strict success as the evaluation metric across any shaping choices. Recheck PrimeRL compatibility and service availability at that time.
7. Before eventual Hub/HF release, resolve derivative licensing, retain upstream/schema/terminology notices, and verify a clean wheel with train/dev only. Do not use public/heldout cases for iterative tuning.
